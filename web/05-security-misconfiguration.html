5. Security misconfiguration

Description. The install that a new operator gets is the open one. A default account. A debug route. A stack trace. A storage bucket that lists. A CORS rule of *. A feature flag that the test turned on does not count. The product's own default does.

Why it matters. The attacker does not need a bug in the business logic. They need the setup the documentation shipped.

Detection hints.

  • Install or read the default config. Do not enable a sample plugin first.
  • Request the admin, debug, and directory routes with no session.
  • Read the error body for a failed login. A stack trace or a query is this class.
  • Invariant: the default config does not serve the admin surface to an anonymous caller, and it

    • does not list the storage root.

Example test. Boot the app with the documented default. Request the debug route with no cookie. Assert 404 or a login wall, and assert the body has no stack frame.

Public references.

  • OWASP Top 10 2021 — A05 Security Misconfiguration
  • OWASP Configuration Cheat Sheet

Field note

A fresh install can ship open: a default account, a debug route, a stack trace, a storage bucket that lists, or CORS *. A feature flag a test turned on does not count. The product's own default does.

No business-logic bug is required. The setup the documentation shipped is enough. OWASP A05:2021 records a 4.51% average incidence and over 208k CWE occurrences, including CWE-16 (configuration).

Detection hint. On the documented default, compare response headers to a hardened baseline. Missing security directives (for example HSTS or a restrictive Content-Security-Policy), or a session cookie without Secure and HttpOnly, is this class. Do not change the config to force a pass.
