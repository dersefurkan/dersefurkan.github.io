1. Broken access control

Description. The server performs an action for a caller who does not own the object and does not hold the role the action requires. The UI hid the button. The check on the server is missing, or it trusts an id, a role, or a tenant the client sent.

Why it matters. This is the class OWASP has ranked first. The state change is someone else's record, file, or invoice. A hidden link that still returns the object is the same class as an id the attacker guessed.

Detection hints.

  • For every object id in a scoped flow, repeat the request as a second user created by the product,

    • not by a test backdoor.

  • Diff the server check: it must compare the session's subject to the object's owner or role. A

    • check that only looks at the id in the query is not a check.

  • Horizontal and vertical are the same test with a different second identity. An admin route is

    • vertical. Another user's invoice is horizontal.

  • Invariant: B's request does not change A's object, and the response does not contain A's secret

    • fields.

Example test. A owns invoice 1. B is logged in. B requests invoice 1. Assert denial and that the amount, status, and owner are unchanged.

Field note

The server acts for a caller who does not own the object and lacks the required role. Hiding a button is not a control. Trusting a client-sent id, role, or tenant is not a check.

OWASP ranks this class first. Harm is another person's record, file, or invoice.

Detection hints:

  • Repeat the request as a second product user, not a test backdoor.
  • Compare the session subject to the owner or role. Matching only the query id is not a check.
  • Horizontal and vertical cases use the same test with a different second identity.
  • B's request must not change A's object or return A's secret fields.
  • No session must be denied on GET, POST, PUT, and DELETE. A write after a blocked read is still this class.

Example: A owns invoice 1. B requests it. Expect denial and unchanged amount, status, and owner.
