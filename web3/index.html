Send the surface

Web3

The identity that moves the money.

One contract family, or one diff under 800 lines. The review asks which number the protocol believes, and which store the code actually updates. A green suite means those properties held. It is not an audit stamp.

What this surface is against

  • A deposit credited on one ledger and missing on the other.
  • A share price that the first depositor can inflate.
  • A fee taken on the balance instead of the gain.
  • An upgrade that keeps the old storage layout and reads the wrong slot.
  • A proof gate that accepts a journal the application did not bind.

What you send

The repo or the diff, the chain if a fork is in scope, and the one identity you care about: shares, receipts, a queue cursor, a fee base. A second system is a second pack.

What you get

A report. Each finding, the evidence, and the fix. On this surface the evidence is a Foundry test that fails on the bug and passes on the patch, because a contract bug comes back when the test is missing. That test stays in a private repo. It is not a service that scans the chain after we leave. Fourteen days to re-run the same tests.

Teaching repos

  • split-ledger-vault-demo — one deposit, two ledgers, then the patched invariants.
  • pool-invariant-suite-demo — inflation and fee creep, handler invariants on the fixed contracts.
  • zk classes — when the money moves because a proof was accepted.

Run forge test in the teaching repos. They are constructed so a property fails and then holds. They are not findings against a live protocol.
